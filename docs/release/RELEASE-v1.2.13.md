# v1.2.13：两处大字统一用 10px 宿主 + 修角色介绍面板折行

日期：2026-10-25。

## 背景与实测证据

- 实机反馈：关卡选择左上角「12 太小」；中央过场标题的「第x关 依然模糊，需要缩小到完美像素大小」。
- 查原版场景数据（level4 / level128-131）：关卡选择与角色介绍都用 UnityEngine.UI.Text（游戏自定义组件，字体设置在嵌套的 m_FontData 里），组件实测 m_RichText=1（支持富文本标签）、m_VerticalOverflow=0（超出即裁切）。
- 角色介绍面板（TextL）的文本框实测 **96 canvas 单位宽**、水平溢出 = Wrap；而中文字形在 fusion 像素字体里是**全角等宽**（10px 下每字 10 单位），日文原字体 07やさしさゴシックボールド 是**比例字体**（片假名较窄）—— 日文放得下的行，中文未必放得下。

## 改动

### 1. 两处大字统一用 10px 宿主，字号取整数倍

| 目标 | 行1 | 行2 |
| --- | --- | --- |
| 关卡选择左上角 | 「第N关」10px（1:1，小字） | 「地名」20px（2×） |
| 中央过场标题 | 「第N关」20px（2×） | 「地名」30px（3×） |

- 译表里的首行标签 <size=16> 是 16/10 = **1.6× 非整数倍** → 字腔与描边都会糊（这正是「第x关 依然模糊」的原因）。译表的标签必须与日文原文逐字节相同（一致性校验），所以**不改表**，而是由插件在运行期改写成 <size=20>；关卡选择的行2 则注入 <size=20>。组件支持富文本，两处都是幂等操作，**译表数据逐字不变**。
- **移除 12px 字体宿主**（v1.2.12 曾新增）：Unity 只实例化「被引用」的资产，新增的 Font 对象无人引用 → 运行期根本不存在（BepInEx 日志实证 12px font host not found），插件退回 10px 宿主后字号反而变成 1.2×/2.4× 非整数倍 → 更糊。写进 PreloadData 也未能让 Unity 实例化它。本版把该宿主（含新增的 Material/Texture 对象）整体移除，产物回到原版的 42 个对象、3 个字体，两处大字统一走游戏自带的 10px 宿主。
- 8px 宿主仍不能用于大字：8px 设计网格里「糖/浆/饼」等密笔画汉字本身没有字腔，2× 放大只会把实心块放大（v1.2.10 实机复测确认）。

### 2. 角色介绍面板折行修正（逐行量宽）

面板内任一行不得超过 96 单位，否则会被迫折行：

| 位置 | 原文 | 宽度 | 修改后 | 宽度 |
| --- | --- | --- | --- | --- |
| 库玛引语首行 | 「　「我才是水中最快的」 | 100 ✘ | 「　「水中最快的龙」 | 80 ✓ |
| 库玛引语次行 | 「　　龙！」」 | 50 | 「　　当然是我！」」 | 70 ✓ |
| 索拉科动作行 | 「⑫ ：冲刺・抓挠攻击」 | 95（仅余 1 单位）✘ | 「⑫ ：冲刺・抓挠」（按日文简写惯例） | 75 ✓ |

其余 6 个角色的引语与全部动作行均 ≤ 90 单位，无需改动。

### 3. 全表排版审计

- 以场景中文本框的实际宽度为基准，核对 104 条能定位到显示框的 UI 表文本：仅 2 条超宽，且**日文原文在同样盒子里同样超宽**（原版就折行），不是本次引入的回归。
- 以「中文总宽是否超过日文总宽」为与盒宽无关的相对判据，核对全表 1411 行：33 行中文更宽，逐条剔除后剩下的都是 ×1.15~1.26 的小项（设置标签、版权行等，盒宽 256 足够），且唯一比例悬殊的 4 行是**中日完全相同的 ASCII 串**（字体宽度差异，非翻译问题）。
- 对话/伤害台词（969 行）的行宽分布：真实剧情行最宽 220 单位，而日文原行在原版比例字体下可达 550 单位 → 中文整体比日文窄，不会多占行数。

## 不变的部分

- 译文其余部分、图片、其它文本策略零改动；游戏自带字体槽位保持原样，日英界面不受影响。
