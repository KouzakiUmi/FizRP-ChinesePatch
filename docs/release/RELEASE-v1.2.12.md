# v1.2.12：两处大字改用 12px 设计字体（新增字体宿主）

日期：2026-10-24。

## 背景

v1.2.10 与 v1.2.11 连续两版都在同一处返工：用户实机反馈「之前模糊还能辨认出字形，这个对齐之后字中间的空间都变成实心了」。

| 版本 | 方案 | 实机结果 | 根因 |
| --- | --- | --- | --- |
| v1.2.9 | 10px 宿主 @14/24（1.4×/2.4×） | 模糊但可辨 | 非整数倍放大 |
| v1.2.10 | 8px 宿主 @16（2×） | **字腔糊成实心** | 8px 设计网格里密笔画汉字本就没有字腔 |
| v1.2.11 | 10px 宿主 @10/20（1:1/2×） | 关卡选择明显偏小 | 框高只容两行 10px；字腔仍被描边挤压 |
| **v1.2.12** | **12px 宿主 @12/24（1:1/2×）** | 待实机确认 | — |

## 根因（离线复现 + 场景取证）

1. **字形承载力是第一道门槛**：把「糖/浆/饼」在 8px 设计网格下放大，只有 8px 与 10px 设计能画出可辨字腔；8px 设计的「糖」本身就是一坨实心块，任何倍率都救不回来。游戏的 `PixelOutline` 描边带固定延伸 1 canvas 单位（实测白笔画 8 设备像素 / 黑间隙 4 设备像素），不随字号缩放，会进一步吃掉密笔画的 1px 间隙。
2. **版式余量是第二道门槛**：实测关卡选择左上角世界名的文本框只有 240×32 canvas 单位，下一行宝珠在 45.8 canvas 单位处；原版日语是 14px、行距 1.0em（两行 28 单位）。所以关卡选择能用的字号上限在 12～13px——10px 明显偏小，20px 会压到宝珠行。
3. 因此唯一同时满足「有字腔」「不撞宝珠」「大小接近原版」的是 **12px 设计 @ 12px（1:1）**；过场标题框 256×224 空间充裕，用 **12px @ 24px（2× 整数倍）**。

## 修复

- 新增 **12px 设计中文字体宿主**：补丁在 `sharedassets0.assets`（载荷本已分发、每个场景都会加载）里**新增一个 Font 对象** `FizRP12pxZhHans`，并为它**单独复制一份 "Font Material" 与 0×0 "Font Texture"**——与游戏自带字体一一对应。动态字体在运行期把字形光栅化进各自的贴图，两个字体共用一张图集会把 10px 与 12px 的同码字形混用、渲染出错字。
- 字体按**译表实际用字 + ASCII 子集化**：1402 字符（子集 glyphOrder 1404）/ 241 KB，避免 7 MB 全量 zh_hans 进载荷。12px 字体无 TrueType hinting（已核实：无 fpgm/prep/cvt、无逐字形指令），子集化保持轮廓逐字节不变，像素网格不受影响。
- 插件新增第 3 个字体槽位缓存该宿主；两处大字按 12px 设计渲染：关卡选择 12px（1:1）、过场标题 24px（2×）。宿主缺失时自动回退到 10px 宿主并在日志告警（`12px font host 'FizRP12pxZhHans' not found`）。
- 像素对齐网格按实际宿主与字号计算：1 设计像素 = fontSize/设计尺寸 个 canvas 单位（12px 宿主 @12px = 1、@24px = 2）。

## 不变的部分

- 译文沿用 v1.2.9，本次不改文案；普通小字 8/10 两档策略不变；对白内 `<size=24>` 富文本、教学板 75px 等其它大字维持原样。
- 保留 13 张中文贴图、10 个 JP 专用切片保护、117 文件精简载荷与 v1.2.7 的暂停提示绝对偏移修复。
