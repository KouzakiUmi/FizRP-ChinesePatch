# v1.2.11：两处大字改用 10px 字体渲染（重做 v1.2.10 的大字方案）

日期：2026-10-24。

## 问题

v1.2.10 把关卡选择左上角世界名与首次到达新关卡的中央过场标题改成「8px 设计字体 + 整数倍放大」。实机复测后**效果反而更差**：用户反馈「之前模糊还能辨认出字形，这个对齐之后字中间的空间都变成实心了」。

## 根因（离线复现 + 场景取证）

- **8px 设计网格里密笔画汉字本就没有字腔**：`糖`/`浆`/`饼` 在 8px 设计下笔画已经粘连成实心块，2× 放大只是把实心块放大 —— 任何倍率都救不回来。10px / 12px 设计才有可辨的「糖」字结构。
- **描边宽度固定**：游戏自研的 `PixelOutline`（`Ruccho.Utilities.PixelOutline`，`effectDistance=(0.5,0.5)`）按 8 方向复制笔画，黑色描边带固定延伸 1 canvas 单位（实测白笔画 8 设备像素 / 黑间隙 4 设备像素），**不随字号缩放**；字号越大描边相对越细，但密笔画的 1px 间隙仍被吃掉。
- 用截图反推标定离线渲染（描边 reach = 1.0 canvas 单位时模拟与实机完全一致），再对 8/10/12px × 多个字号做量化对比，结论一致：8px 承载不了这批字。

## 修复

- 两处大字统一改用 **10px 设计宿主**（k8x12EXS，即普通小字的大档宿主，不新增字体槽位）：
  - 关卡选择左上角世界名：**10px（1:1）**。其文本框实测 240×32 canvas 单位，两行 10px 行高 1.4em 合计 28px 恰好容纳；12px 起即溢出被裁。
  - 中央过场标题：**20px（2× 整数倍）**。文本框 256×224 空间充裕；2× 放大后字腔完整、笔画粗壮。首行由译表 `<size=16>` 固定为 16px，不受此处 fontSize 影响。
- **8px 宿主彻底退出大字用途**，回归常规小字的 1:1 渲染。
- 像素对齐网格改为按实际宿主与字号计算：1 设计像素 = fontSize/设计尺寸 个 canvas 单位（8/10px 小字 = 1，大字 20px@10 设计 = 2），内容起点对齐到该网格整数倍；非整数倍时保守退回 1。
- 修正交叉核验发现的阻断项：`[snap]` 日志格式串占位符（13 个）多于实参（12 个）导致的运行时 `FormatException`；并补一条静态回归测试防止复发。
- 同步更新过期注释与 `fonts.config.json` 的角色说明。

## 不变的部分

- 译文沿用 v1.2.9，本次不改文案；普通小字 8/10 两档策略不变；对白内 `<size=24>` 富文本、教学板 75px 等其它大字维持原样。
- 保留 v1.2.8 的过场标题字号策略、13 张中文贴图与 10 个 JP 专用切片保护、117 文件精简载荷，以及 v1.2.7 的暂停提示绝对偏移修复。
